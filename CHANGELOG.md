# Changelog

All notable changes to Sinew for Kotlin are documented here. Every module shares one version (lockstep).

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

## [Unreleased]
- S7 publishing setup (#38): every module and the BOM are ready for Maven Central, and CI proves a consumer can use them.
  - The BOM uses the `com.srctool.publish` convention plugin like the modules (POM, signing), so all 15 artifacts are published the same way.
  - ABI validation is part of that convention now: every published module has its public API dumped under `api/` and checked by `check` (`checkKotlinAbi`), not only the three devtools modules. A change to a public API fails the build until `updateKotlinAbi` is run and the dump committed.
  - `tool/verify-publish.sh <version>` publishes the whole set to Maven Local, then compiles `tool/consumer-check`, a separate Kotlin Multiplatform project that depends on the BOM alone, on Android, iOS (device and simulator), the JVM and wasm. Its code is the usage docs' samples, and it uses `sinew-testing` as a test dependency. The `publish-check` CI job runs it on every pull request.
  - Every module's publication has a sources jar and a javadoc jar, and the POM carries the name, description, URL, license, developer and SCM that Central checks.
- S7 API reference (#88): every public declaration has KDoc, and the build fails on one that doesn't.
  - Dokka is applied to every library module by the `com.srctool.publish` convention plugin, with `reportUndocumented` on and `failOnWarning`, so an undocumented public declaration, or a broken `[link]` in a doc, fails `dokkaGenerate`. CI runs it on every pull request.
  - About 280 declarations were documented across `sinew-models`, `sinew-exception`, `sinew-network`, `sinew-testing`, `sinew-storage`, `sinew-security`, `sinew-paging`, `sinew-devtools` and `sinew-devtools-ui`. `PagingState`'s doc had a broken link, now fixed.
  - `sinew-devtools-noop` is the one exception: it has no behavior and mirrors the real devtools' API (checked by `checkDevtoolsNoopAbi`), so its `Module.md` says so instead of repeating the real docs.
  - The publish workflow builds the reference before publishing and attaches it to the GitHub Release as `sinew-kotlin-api-<version>.zip`, one folder per module.
- S7 Kotlin README (#87): the README for the 1.0 release.
  - A Maven Central badge, getting started with the BOM, the devtools wiring per platform, a first screen taken from the sample, a table of every module, and links to the usage docs, the API reference and the Guide.
  - It says 1.0.0 is in preparation; the release (#40) changes that line.
- S7 usage docs samples (#89): the Kotlin code the usage site shows is real code.
  - `:sample:docs` is a JVM module of the samples (models, errors, paging, presentation, network, stores, cipher, vault and tests), compiled by CI, and its two tests run. Each sample sits between `// region` lines, which the site copies, so a documented call that stops existing fails the build.
  - The sample app's view model, screen and devtools wiring have region markers too, so the quick start and the production guide quote the code that runs.
- S7 Camouflage from Maven Central (#85): Sinew builds against Camouflage's released `0.1.0` instead of its source.
  - `gradle/camouflage.versions.toml` holds `0.1.0`. The `third_party/camouflage-kotlin` submodule, its `includeBuild` and `submodules: true` in CI are gone, so the build, the tests and the sample run against the artifacts consumers get, and the publish job has no source dependency to refuse.
  - Nothing Sinew uses changed between the old pin and `0.1.0` (the Carbon skin and Camouflage's accessibility checks). The sample's list screen runs its full cycle on the JVM, iOS and wasm against it.
- S6 devtools gating in CI (#47): the `devtools-gating` job proves production builds carry no devtools code.
  - `checkDevToolsGating` builds the sample's production outputs (Android release APK, desktop uber jar, wasm bundle, and on macOS the `iosArm64` release framework) and fails if any holds a `com.srctool.sinew.devtools` declaration that `sinew-devtools-noop` doesn't declare.
  - The real-devtools builds are checked the opposite way (the Android staging release, and the rest with `-Psinew.devtools=true`), so a search that can't see devtools code fails instead of passing.
- S6 `sinew-devtools-noop` (#46): the stand-in production builds depend on.
  - It declares exactly what `sinew-devtools` and `sinew-devtools-ui` declare together, in the same packages, with nothing behind it: nothing is recorded, the hooks are `SinewHttpHooks.None`, `SinewDevTools { content }` only calls `content()`, and `DevToolsMenuItem` draws nothing. Where a value must come back it's the safe one: every name counts as sensitive, and no body is kept.
  - Kotlin's ABI validation is on for the three modules, with reference dumps under each module's `api/`. `checkDevtoolsNoopAbi`, in CI, compares the no-op's JVM, Android and klib dumps with the real two together. It ignores what the Compose compiler generates (`ComposableSingletons`, `$stable`, `$stableprop`).
  - The sample's four entry points wrap the app in `SinewDevTools`, and CI builds the Android production release, which takes the no-op, so the same code compiles against both artifacts.
- S6 `sinew-devtools-ui` (#45): the overlay and every built-in page.
  - `SinewDevTools(sections, ribbon, launcher, redaction, stores, changelog, hosts, showUncaughtErrors, preferences) { App() }` and `DevToolsMenuItem`, on Compose Material 3 with its own theme and back stack. System Back walks that stack, through `NavigationBackHandler` when the app provides a dispatcher.
  - The entry contract: `DevToolSection`, and `DevToolEntry.Page`, `Group`, `Toggle` and `Action`, with `confirm` asking first. `BuildRibbon`, and the launchers `FloatingLauncher` (draggable, a drag never opens it, its position remembered in `preferences`), `MenuLauncher` and `CustomLauncher`. Sinew's section is first, the app's follow.
  - The pages:
    - Network Monitor, with Copy, Copy as cURL, and Replay: a GET replays on tap, other methods ask first, and a record that can't be replayed is disabled with its reason.
    - Exception Log, with Copy.
    - Key-Value Store: edits by the value's own type, deletes after asking.
    - Secure Store: masked, never copyable, "Clear all" after asking.
    - Local DB, read-only.
    - Expire Access Token, Fault Injection, API Host and Changelog.
  - The ribbon adds the active host and "faults on". An optional card shows uncaught errors.
  - `DevTools.open()`, `close()` and `isOpen`. The recorders' `redaction` can be set, so `SinewDevTools(redaction = …)` applies the app's rules.
  - Tests:
    - Compose UI tests run on the JVM, iOS and wasm.
    - Robolectric UI tests and Roborazzi screenshots run on the Android host. Roborazzi screenshots also run on the desktop.
    - Screenshot references live per OS under `screenshots/<os>/`, and CI uploads the Linux set it records.
  - Build:
    - Android host tests include Android resources in every module, so Robolectric can render Compose.
    - Mocha's browser timeout is 15 s.
- S6 `sinew-network` and `sinew-devtools` (#44): devtools' way into a client.
  - `SinewHttpHooks` (`attached`, `detached`, `hostOverride`, `fault`, `record`; `None` by default) and the `SinewHooks` plugin, installed by the preset **inside** `SinewAuth`, so a forced 401 runs the real refresh and each replay after a refresh is recorded on its own. `SinewHttp.client(…, hooks = …)` takes them, and so does `mockHttp`.
  - A `FaultDecision` waits, drops the connection (classified as `NoInternetConnectionException`, like a real drop) or answers a status and body without reaching the network. That answer goes through `HttpClientCall`'s `@InternalAPI` constructor, the only way to fake a response in Ktor.
  - `SinewHttp.debugExpireToken(client)`: the next request that carries a token sends an invalid one, so the real 401 → refresh runs. `SinewAuth` is unchanged.
  - Devtools: `FaultRule` and `FaultRules` (in memory only, newest match wins, path patterns that match the end of the path, `*` for any run), `HostOverride` (the app's hosts, the choice remembered in `sinew.devtools.apiHost`, a stored host the app no longer lists forgotten), and `DevTools.httpHooks`, `faults`, `hosts`, `canReplay`, `replay` and `expireAccessToken`.
  - A replay goes through the client that sent the record, so the auth layer adds a fresh token and the client its own headers. Faults and the host override apply, and the result is a new record marked as a replay. A record that lost a secret, was cleared, or whose client closed can't be replayed.
- S6 `sinew-devtools` (#43): the recorders.
  - `NetworkRecorder` (capacity 200, newest first, a `StateFlow`): `record(NetworkExchange)` redacts before storing, using the client's `defaultHeaders` too. `recordCacheServe` covers responses served from a cache.
  - `NetworkRecord.replayable` is true only when nothing but `Authorization` or the client's own headers lost a value and the body wasn't cut or binary. `asText()` and `asCurl()` give the redacted record.
  - `ExceptionRecorder` (capacity 50): repeats with the same type, code, message and source within 2 s of the last are merged into one row with a count, moved to the top. Messages and stack traces go through the new `Redaction.redactText`, which masks credentials and sensitive `name=value` and JSON pairs in free text.
  - `DevToolsCrashReporter(wrapping)` sends every report to the log, then on to the real reporter unchanged.
  - `DevTools.captureUncaughtErrors()` chains into the platform's uncaught-error hook: the default handler on Android and the JVM, `setUnhandledExceptionHook` on iOS, and the window's `error` and `unhandledrejection` events on the web. `DevTools.coroutineHandler` records uncaught coroutine failures.
  - `DevTools.clearUserData()` empties the network records.
- S6 `sinew-devtools` (#42): `Redaction`, which masks secrets before anything is stored. Names are normalized (lowercased, without `_`, `-` and `.`) and matched by part (`password`, `token`, `secret`, `otp`, `pin`, `apikey`, …) or whole (`code`), in headers, query parameters, form bodies and JSON bodies at any depth. `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization` and every `defaultHeaders` name (`withHeaders`) are masked. A JSON body that doesn't parse is masked whole; binary bodies keep only type and size (`RecordedBody`), and a text body says whether anything in it was hidden (`masked`, so a request that lost a secret is never replayed); fragment parameters (`#access_token=…`) are redacted like the query; text is cut at 64 KB after redaction, keeping its real size. `Redaction.Default + { … }` can't remove a default. `Redaction.maskSecret` shows a stored secret as `•••• 9f2c (412 chars)`, or only its length under 16 characters. Replaces the S0 placeholder.

- S5 `sinew-testing` (#33): `TestScope.mockHttp(config, tokenSource, logger) { on(method, path).respond(status, body, headers, delay) / .drop() }`, a real `SinewHttp` client on Ktor's mock engine that records requests (`requests`, `requests(method, path)`), answers a route's responses in order and repeats the last, fails the test on an unmatched request, runs the engine and refreshes on the test's scheduler (delays and deadlines in virtual time), and drops a connection with the platform engine's own error. `fixture(name)` reads `src/commonTest/resources/<name>` on every target (the classpath; `SINEW_TEST_RESOURCES` on the iOS simulator; `/base/kotlin/<name>` through Karma on wasm, set up by `tool/karma.config.d`), failing with the path when it's missing. `withRecordingReporter { reporter -> }` restores the previous reporter even when the block fails. `TestScope.controlledFetch()` fails the test when a call is left unanswered. `sinew-network`: the `SinewHttp.client` overload with `refreshContext` is public, for tests. `checkSinewGraph` now allows `sinew-testing` only from `commonTest`.
- S5 `sinew-testing` (#32): a fake for every Sinew interface. `FakeKeyValueStore` (a wrong type reads as absent; `failNextRead`, `failNextWrite`, `failNextWriteWithDiskFull`), `FakeSecureStore` (`failNextRead`, `failNextWrite`, `loseKey`), `FakeFieldCipher` (no cryptography: a readable `enc(…)` / `enc[context](…)` form; `failNextDecrypt`, `rotations`), `FakeBiometricVault` (settable availability, `nextStore`/`nextUnlock` failures, `invalidate`, `prompts`), `FakeRefreshTokenStore`, `RecordingCrashReporter` (`reports`, `codes`, `clear`), `FakeLocalizer` (a map with `{name}` arguments, the key itself or `null` when missing, `requested`) and `RecordingHttpLogger`, beside `FakeTokenSource` and `FakeNetworkChecker`. `platformStorageError()` and `diskFullError()` throw what each platform's store throws (`java.io.IOException`, okio's `IOException` on iOS, a browser `DOMException` on wasm), so an app's `processStorageCall` classifies a fake's failure as a real one's. Every fake has tests on all four targets.
- S4 CI (#30): the `android-device` job runs the `sinew-security`, `sinew-storage` and `sinew-network` device tests on an API 35 emulator; `tool/android-device-test.sh` runs them locally module by module.

- S4 `sinew-storage` (#28): `processStorageCall(module, function, access, block)`, `StorageAccess` (`Read`, `Write`) and the public `storageHandlers` table: corruption (`DecryptionFailed`, DataStore's `CorruptionException`, `SerializationException`) → `LocalStorageCorruptionException`; out of space (`ENOSPC` text, SQLite's "database or disk is full", `SQLiteFullException`, `QuotaExceededError`) → `StorageFullException`; other storage errors (I/O, SQLite, browser storage `DOMException`s) → `StorageReadException` / `StorageWriteException` by access; `EnvelopeDataMissing` → `ParseException`. Matches anywhere in the cause chain.
- S4 `sinew-storage` (#27): `SecureStore` (`read`, `write`, `delete`, `clearUserData`, `SecureStore.create(PlatformContext, namespace)`; the JVM's `create(directory, namespace)`): one store on every target, a dedicated `<namespace>_secure` `KeyValueStore` whose values `FieldCipher` encrypts with `<namespace>:<key>` as associated data (ADR-26). A value that can't be decrypted reads as absent and is deleted; writes are serialized; a reinstall starts empty because the data goes with the app. Android device tests for `sinew-storage`.
- S4 `sinew-storage` (#26): `KeyValueStore` (`getString`/`getInt`/`getBool`/`getDouble` and setters, `remove`, `clear`, `KeyValueStore.create(PlatformContext, name)`): DataStore Preferences on Android, iOS (Application Support) and the JVM (the app-data folder, or `create(directory, name)`), one DataStore per file per process; `localStorage` with prefixed, type-tagged values on wasm. A value read as another type is absent. Replaces the S0 placeholder.
- S4 `sinew-security` (#25): `BiometricVault` (`availability`, `isStored`, `store(secret, reason)`, `unlock(reason)`, `disable`, `BiometricVault.create(PlatformContext, keyAlias, clearOnReinstall)`) with `BiometricStore`, `BiometricUnlock` (its `toString` never shows the secret), `BiometricAvailability` and `BiometricFailure`. Android: an AES-256-GCM Keystore key needing a strong biometric match for every use, invalidated by a new enrollment, unlocked through `BiometricPrompt` with a `CryptoObject` (so storing prompts too), on the resumed `FragmentActivity`, never overlapping a prompt that's still closing. iOS: a Keychain item with `biometryCurrentSet` access control, this device only, cleared on the first use after a reinstall (`InstallMarker`, one marker per owner). JVM and wasm: `Unavailable`. `sinew-security` now depends on `kotlinx-coroutines-android` on Android. Test tooling: `tool/ios-app-test.sh` runs `*AppHostTest` classes as an app on the simulator with the Keychain and simulated Face ID (`-Psinew.iosAppHost` links the entitlements), and `tool/android-biometric-test.sh` answers fingerprint prompts on an emulator; the `FieldCipher` contract now also runs against the real iOS Keychain.
- S4 `sinew-security` (#24): `FieldCipher` (`encrypt`, `decrypt`, `rotateKey`, `FieldCipher.create(PlatformContext, keyAlias)`) and `DecryptionFailed`: AES-256-GCM with `context` as associated data and one layout on every target (`version | key id | nonce | ciphertext | tag`, Tink's `TINK` output). Tink with an Android Keystore master key on Android (a lost master key starts a fresh keyset), Tink with an owner-only keyset file on the JVM (`create(directory, keyAlias)` too), CryptoKit through cryptography-kotlin with the keyring in the Keychain on iOS, and Web Crypto with a non-extractable key in IndexedDB on wasm. `sinew-security` now depends on `sinew-models`, for `PlatformContext` only; replaces the S0 placeholder.
- S3 `sinew-network` (#63): certificate pinning. `SinewConfig.certificatePins` (SHA-256 public-key pins for the base URL's host, validated up front), applied by the preset on OkHttp (`CertificatePinner`) and Darwin (Ktor's `CertificatePinner`); `pinCertificates(host, pins)` on `OkHttpConfig` and `DarwinClientEngineConfig`; an engine that can't pin fails at build time; ignored on wasm. A pinning failure suppressed behind another route's connection error is no longer classified as offline.
- S3 `sinew-network` (#22): `NetworkChecker` (`status: StateFlow<NetworkStatus>`, `isOnline()`, `close()`, `NetworkChecker.create(PlatformContext)`): Android's validated default network (with `ACCESS_NETWORK_STATE` in the library manifest), iOS `NWPathMonitor`, a JVM interface poll every 5 seconds, and the browser's `online`/`offline` events. Android device tests (`androidDeviceTest`) for `sinew-network`. `sinew-testing`: `FakeNetworkChecker`.
- S3 `sinew-network` (#21): `retryWithBackoff` (exponential backoff with full jitter, capped at `maxDelay`; a 429 waits at least `retryAfter`, or is returned at once when that's longer than `maxDelay`; the last failure returned unchanged) and `poll` (1.5× growth with equal jitter up to `maxInterval`; retryable failures keep polling; `PollingTimeOutException` with the last failure as its cause).
- S3 `sinew-network` (#20): `processApiCall` and `processOptionalApiCall` (a 404 is `null`): envelope `failure()` → `ValidationException` or `ApiErrorException` before `toDomain()`, `message()` → `Success.message`. The public `apiHandlers` table (timeouts and lost connections anywhere in a failure's cause chain, never when a TLS or certificate failure is in it; every 5xx but 503 and 504 → `ServerException`; 408 to the catch-all; unreadable JSON and a missing payload → reported `ParseException`), with per-platform predicates for OkHttp, Darwin and the browser, and Ktor's own `ResponseException` classified by status. `RefreshResult.from(result)` for a guarded refresh call.
- S3 `sinew-network` (#19): `SinewAuth` (the token only for `baseUrl`'s host and port outside the exact anonymous paths; one refresh for any number of 401s through `SingleFlightRefresher` in the client's scope; a 401 for an older token replays at once; one replay per request; `Rejected` and a replayed 401 return the 401; `Unavailable` throws its cause and keeps the session; a request's own `Authorization` and a 401 after sign-out are left alone; a one-shot body refreshes but isn't replayed), `SinewHttp.resetAuth`, and `SessionTokenSource` with `RefreshTokenStore`, `RefreshCall` and `RefreshResult` (session epoch, `start`, `onSessionEnded`, a rejection ending only the session it started in). Every layer is now a public plugin installable alone (`sinewBackend(url)`, which sets `defaultRequest` and gives the plugins the base URL once, `SinewAuth`, `SinewHeaders`, `SinewTimeouts`, `SinewRedirect` with `maxHops`, `SinewLog`, and `HttpResponseValidator { sinewErrorBody() }`), each failing fast on a missing setting; `SinewHttp.client` is the optional preset built from them and now takes the `TokenSource`. `sinew-testing`: `FakeTokenSource`.
- S3 `sinew-network` (#18): `SinewHttp.client` on the platform engine or an explicit one (OkHttp, Darwin, Js), with `SinewJson`, per-method deadlines that a request's own `timeout { }` overrides, the JSON, language and default headers read per request, a validator that reads failed bodies with the config's `ErrorBodyReader` and throws after redirects, `SinewRedirect` (GET/HEAD, five hops, no HTTPS downgrade, `Authorization` and `Cookie` dropped across hosts) and `SinewLog` with `HttpLogger` (one line per exchange, never a header, body or query).
- S3 `sinew-network` (#17): `SinewConfig` (validated on construction; `locale` and `defaultHeaders` read per request), `TokenSource` with `RefreshOutcome` (`Refreshed`, `Rejected`, `Unavailable(cause)`) and the `clear()` epoch contract, `ErrorBodyReader` with a `Default` that reads JSON `message` and `errors`, and the internal `HttpStatusError(status, errorBody, retryAfter)` with `Retry-After` in seconds or an HTTP date; replaces the S0 placeholder.
- S2 `sinew-viewmodel`: `StateEffectViewModel` and `EventActionViewModel` on the multiplatform AndroidX `ViewModel` (actions in `viewModelScope`, clean-up through `addCloseable`, events after clearing ignored) and `ObserveEffects` (`repeatOnLifecycle(STARTED)` on `Dispatchers.Main.immediate`); replaces the S0 placeholder.
