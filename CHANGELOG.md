# Changelog

All notable changes to Sinew for Kotlin are documented here. Every module shares one version (lockstep).

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

## [Unreleased]
- Build: Kotlin 2.4.21. On 2.4.20 the wasm compiler emits an invalid `deserialize` for a `@Serializable` class whose type parameter is bounded by a later one (`ObjectResponse<T : Remote<D>, D : Domain>(val data: T?)`), so the browser can't load the module; `sinew-models`' wasm tests failed this way, and so would an app's envelope of that shape. The Compose convention plugin declares `binaries.executable()` on the wasmJs target, which Compose UI browser tests need (CMP-4906); the published artifacts are unchanged. CI's `web` job now runs `wasmJsBrowserTest`.
- S5 `sinew-testing` (#32): a fake for every Sinew interface. `FakeKeyValueStore` (a wrong type reads as absent; `failNextRead`, `failNextWrite`, `failNextWriteWithDiskFull`), `FakeSecureStore` (`failNextRead`, `failNextWrite`, `loseKey`), `FakeFieldCipher` (no cryptography: a readable `enc(…)` / `enc[context](…)` form; `failNextDecrypt`, `rotations`), `FakeBiometricVault` (settable availability, `nextStore`/`nextUnlock` failures, `invalidate`, `prompts`), `FakeRefreshTokenStore`, `RecordingCrashReporter` (`reports`, `codes`, `clear`), `FakeLocalizer` (a map with `{name}` arguments, the key itself or `null` when missing, `requested`) and `RecordingHttpLogger`, beside `FakeTokenSource` and `FakeNetworkChecker`. `platformStorageError()` and `diskFullError()` throw what each platform's store throws (`java.io.IOException`, okio's `IOException` on iOS, a browser `DOMException` on wasm), so an app's `processStorageCall` classifies a fake's failure as a real one's. Every fake has tests on all four targets.
- S4 CI (#30): the `android-device` job runs the `sinew-security`, `sinew-storage` and `sinew-network` device tests on an API 35 emulator; `tool/android-device-test.sh` runs them locally module by module.
- S4 `sinew-storage` (#29): `pagedQuery(page, limit, firstPage, fetch)`, fetching `limit + 1` rows so `hasNextPage` needs no count query, with `hasPreviousPage` and argument checks; `InspectableStore` (`name`, `keys()`, `read(key)`), implemented by `KeyValueStore` and `SecureStore` for the devtools.
- S4 `sinew-storage` (#28): `processStorageCall(module, function, access, block)`, `StorageAccess` (`Read`, `Write`) and the public `storageHandlers` table: corruption (`DecryptionFailed`, DataStore's `CorruptionException`, `SerializationException`) → `LocalStorageCorruptionException`; out of space (`ENOSPC` text, SQLite's "database or disk is full", `SQLiteFullException`, `QuotaExceededError`) → `StorageFullException`; other storage errors (I/O, SQLite, browser storage `DOMException`s) → `StorageReadException` / `StorageWriteException` by access; `EnvelopeDataMissing` → `ParseException`. Matches anywhere in the cause chain.
- S4 `sinew-storage` (#27): `SecureStore` (`read`, `write`, `delete`, `clearUserData`, `SecureStore.create(PlatformContext, namespace)`; the JVM's `create(directory, namespace)`): one store on every target, a dedicated `<namespace>_secure` `KeyValueStore` whose values `FieldCipher` encrypts with `<namespace>:<key>` as associated data (ADR-26). A value that can't be decrypted reads as absent and is deleted; writes are serialized; a reinstall starts empty because the data goes with the app. Android device tests for `sinew-storage`.
- S4 `sinew-storage` (#26): `KeyValueStore` (`getString`/`getInt`/`getBool`/`getDouble` and setters, `remove`, `clear`, `KeyValueStore.create(PlatformContext, name)`): DataStore Preferences on Android, iOS (Application Support) and the JVM (the app-data folder, or `create(directory, name)`), one DataStore per file per process; `localStorage` with prefixed, type-tagged values on wasm. A value read as another type is absent. Replaces the S0 placeholder.
- S4 `sinew-security` (#25): `BiometricVault` (`availability`, `isStored`, `store(secret, reason)`, `unlock(reason)`, `disable`, `BiometricVault.create(PlatformContext, keyAlias, clearOnReinstall)`) with `BiometricStore`, `BiometricUnlock` (its `toString` never shows the secret), `BiometricAvailability` and `BiometricFailure`. Android: an AES-256-GCM Keystore key needing a strong biometric match for every use, invalidated by a new enrollment, unlocked through `BiometricPrompt` with a `CryptoObject` (so storing prompts too), on the resumed `FragmentActivity`, never overlapping a prompt that's still closing. iOS: a Keychain item with `biometryCurrentSet` access control, this device only, cleared on the first use after a reinstall (`InstallMarker`, one marker per owner). JVM and wasm: `Unavailable`. `sinew-security` now depends on `kotlinx-coroutines-android` on Android. Test tooling: `tool/ios-app-test.sh` runs `*AppHostTest` classes as an app on the simulator with the Keychain and simulated Face ID (`-Psinew.iosAppHost` links the entitlements), and `tool/android-biometric-test.sh` answers fingerprint prompts on an emulator; the `FieldCipher` contract now also runs against the real iOS Keychain.
- S4 `sinew-security` (#24): `FieldCipher` (`encrypt`, `decrypt`, `rotateKey`, `FieldCipher.create(PlatformContext, keyAlias)`) and `DecryptionFailed`: AES-256-GCM with `context` as associated data and one layout on every target (`version | key id | nonce | ciphertext | tag`, Tink's `TINK` output). Tink with an Android Keystore master key on Android (a lost master key starts a fresh keyset), Tink with an owner-only keyset file on the JVM (`create(directory, keyAlias)` too), CryptoKit through cryptography-kotlin with the keyring in the Keychain on iOS, and Web Crypto with a non-extractable key in IndexedDB on wasm. `sinew-security` now depends on `sinew-models`, for `PlatformContext` only; replaces the S0 placeholder.
- S3 `sinew-network` (#63): certificate pinning. `SinewConfig.certificatePins` (SHA-256 public-key pins for the base URL's host, validated up front), applied by the preset on OkHttp (`CertificatePinner`) and Darwin (Ktor's `CertificatePinner`); `pinCertificates(host, pins)` on `OkHttpConfig` and `DarwinClientEngineConfig`; an engine that can't pin fails at build time; ignored on wasm. A pinning failure suppressed behind another route's connection error is no longer classified as offline.
- S3 `sinew-network` (#22): `NetworkChecker` (`status: StateFlow<NetworkStatus>`, `isOnline()`, `close()`, `NetworkChecker.create(PlatformContext)`): Android's validated default network (with `ACCESS_NETWORK_STATE` in the library manifest), iOS `NWPathMonitor`, a JVM interface poll every 5 seconds, and the browser's `online`/`offline` events. Android device tests (`androidDeviceTest`) for `sinew-network`. `sinew-testing`: `FakeNetworkChecker`.
- S3 `sinew-network` (#21): `retryWithBackoff` (exponential backoff with full jitter, capped at `maxDelay`; a 429 waits at least `retryAfter`, or is returned at once when that's longer than `maxDelay`; the last failure returned unchanged) and `poll` (1.5× growth with equal jitter up to `maxInterval`; retryable failures keep polling; `PollingTimeOutException` with the last failure as its cause).
- S3 `sinew-network` (#20): `processApiCall` and `processOptionalApiCall` (a 404 is `null`): envelope `failure()` → `ValidationException` or `ApiErrorException` before `toDomain()`, `message()` → `Success.message`. The public `apiHandlers` table (timeouts and lost connections anywhere in a failure's cause chain, never when a TLS or certificate failure is in it; every 5xx but 503 and 504 → `ServerException`; 408 to the catch-all; unreadable JSON and a missing payload → reported `ParseException`), with per-platform predicates for OkHttp, Darwin and the browser, and Ktor's own `ResponseException` classified by status. `RefreshResult.from(result)` for a guarded refresh call.
- S3 `sinew-network` (#19): `SinewAuth` (the token only for `baseUrl`'s host and port outside the exact anonymous paths; one refresh for any number of 401s through `SingleFlightRefresher` in the client's scope; a 401 for an older token replays at once; one replay per request; `Rejected` and a replayed 401 return the 401; `Unavailable` throws its cause and keeps the session; a request's own `Authorization` and a 401 after sign-out are left alone; a one-shot body refreshes but isn't replayed), `SinewHttp.resetAuth`, and `SessionTokenSource` with `RefreshTokenStore`, `RefreshCall` and `RefreshResult` (session epoch, `start`, `onSessionEnded`, a rejection ending only the session it started in). Every layer is now a public plugin installable alone (`sinewBackend(url)`, which sets `defaultRequest` and gives the plugins the base URL once, `SinewAuth`, `SinewHeaders`, `SinewTimeouts`, `SinewRedirect` with `maxHops`, `SinewLog`, and `HttpResponseValidator { sinewErrorBody() }`), each failing fast on a missing setting; `SinewHttp.client` is the optional preset built from them and now takes the `TokenSource`. `sinew-testing`: `FakeTokenSource`.
- S3 `sinew-network` (#18): `SinewHttp.client` on the platform engine or an explicit one (OkHttp, Darwin, Js), with `SinewJson`, per-method deadlines that a request's own `timeout { }` overrides, the JSON, language and default headers read per request, a validator that reads failed bodies with the config's `ErrorBodyReader` and throws after redirects, `SinewRedirect` (GET/HEAD, five hops, no HTTPS downgrade, `Authorization` and `Cookie` dropped across hosts) and `SinewLog` with `HttpLogger` (one line per exchange, never a header, body or query).
- S3 `sinew-network` (#17): `SinewConfig` (validated on construction; `locale` and `defaultHeaders` read per request), `TokenSource` with `RefreshOutcome` (`Refreshed`, `Rejected`, `Unavailable(cause)`) and the `clear()` epoch contract, `ErrorBodyReader` with a `Default` that reads JSON `message` and `errors`, and the internal `HttpStatusError(status, errorBody, retryAfter)` with `Retry-After` in seconds or an HTTP date; replaces the S0 placeholder.
- S2 `sinew-viewmodel`: `StateEffectViewModel` and `EventActionViewModel` on the multiplatform AndroidX `ViewModel` (actions in `viewModelScope`, clean-up through `addCloseable`, events after clearing ignored) and `ObserveEffects` (`repeatOnLifecycle(STARTED)` on `Dispatchers.Main.immediate`); replaces the S0 placeholder.
- S2 `sinew-presentation`: `EffectEmitter` (buffered, delivered once, dropped beyond 64), `StateEffectHandler` (`StateFlow` state, `setState`, `emitEffect`, `dispose` closing effects and cancelling the scope) and `EventActionHandler` (`onEvent` → pure `mapEventToAction` → `onAction` launched in the scope; events after `dispose` ignored); replaces the S0 placeholder.
- S2 `sinew-paging`: `LoadType`, `PagingState` (`canLoadMore`, `retryType`), the four strategies behind `Pager.offset`, `offsetByTotal`, `cursor` and `lastItem` (the requested page wins; cursor and last-item have-next rules), and `Pager.load` (`Mutex`, child-job fetches cancelled when superseded, stale responses dropped by request id, `Initial` once per query, `itemKey` de-duplication) and `cancel()`. `sinew-testing`: `ControlledFetch`. `checkSinewGraph` allows `sinew-testing` from test source sets only.
- S1 `sinew-l10n`: `SinewStrings` (keys, suspending `resolve` for a key, arguments and resource environment) and `rememberSinewLocalizer` (the app's strings first, then Sinew's from a per-language preloaded cache); fixes the English apostrophes, which Compose resources don't unescape; replaces the S0 placeholder. `rateLimitedNoTime`'s English fallback now matches its resource.
- S1 `sinew-exception`: the 19 built-in types (no `CancelException` on Kotlin), `ExceptionHandler`, `envelopeDataMissing`, `processCall` (cancellation first, pass-through, first-match handlers, reporting of unexpected and parse failures), `processResult`, `CrashReporter` (`None`, `install`, `current`), `Localizer` and `displayMessage`; replaces the S0 placeholder.
- S1 `sinew-models`: `Domain`, `Remote`, `Entity`, `PlatformContext`; the error base contract (`SinewException` with `errorMessage`, `ExceptionLayer`, `ErrorMessage`, `EnvelopeDataMissing`); `Envelope` with the optional `failure()` and `message()` hooks, `EnvelopeFailure`, the four envelope bases, `PagingMetaEnvelope` and the `DomainNotParsed` stub serializer; `PagingDomain`, `PagingMetaDomain`, `PagingEntity`, `ViewState`, and Sinew's own `Result` (`Success(data, message)` / `Failure(error)`) in place of `kotlin.Result`.
- S0: project skeleton. One Kotlin Multiplatform module per Sinew package (Android, iOS, JVM, wasmJs), the `com.srctool.*` convention plugins, split version catalogs, the dependency-graph check, the BOM and the sample app.
